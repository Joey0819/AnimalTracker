# ID Churn 严重问题解决方案

**问题**: 309个ID / 4条稳定轨迹 = **76倍 Churn 率**（正常 <1.5倍）

---

## 根本原因分析

| 原因 | 说明 | 检测方法 |
|------|------|----------|
| **检测不稳定** | 同一只小鼠在不同帧置信度波动大，导致轨迹频繁丢失 | 平均检测数 < 2 |
| **误检过多** | 低置信度检测被当作新轨迹创建 | 置信度阈值过高 |
| **位置抖动** | 检测框位置不稳定导致匹配失败 | max_distance 过大 |
| **外观相似** | 4只小黑鼠外观高度相似，容易混淆 | 缺少外观区分 |

## 技术原理

### vmTracker v2.0 的 ID Churn 防御

```python
# 1. 多层过滤才创建新 ID
if confidence < 0.5:  # 置信度门槛
        continue

if too_close_to_existing_tracks:  # 位置检查
        continue

if too_similar_to_existing_tracks:  # 外观检查
        continue

# 只有通过所有检查才创建新轨迹
self._init_track(det)
```

### 双锚点系统
```
小鼠1: [头部特征 + 躯干特征] → 即使头部被遮挡，躯干仍可锚定ID
小鼠2: [头部特征 + 躯干特征] → 冗余设计确保稳定性
```

### Zombie Track
```
正常追踪:   轨迹A → 轨迹A → 轨迹A → [丢失] → 删除
Zombie Track: 轨迹A → 轨迹A → [Kalman预测] → 轨迹A (恢复)
```
